# `mvpa_l2.ipynb` Cell Goals and Rules

Generated from the uploaded notebook `mvpa_l2(3).ipynb`.

## Purpose

`mvpa_l2.ipynb` is the manuscript-facing review layer for the NARSAD vicarious safety/threat MVPA L2 results. It should not be treated as the primary modeling script. Its job is to load already generated L2 outputs, audit pipeline compliance, organize the results by prespecified aims, display tables/figures, and preserve the distinction between confirmatory, secondary, contextual, and sensitivity analyses.

The notebook should remain aligned with `PROJECT_CONTEXT.md`. When there is a conflict, `PROJECT_CONTEXT.md` is the canonical guide, and the notebook should be revised to match it.

## Global rules to follow

1. **Preserve the analysis hierarchy.** Primary confirmatory tests must appear before secondary/contextual and sensitivity analyses.
2. **Do not change the main structure unless explicitly requested.** The current order is: setup, data availability, compliance/reproducibility checks, subject/feature counts, Aim 1, Aim 2, Aim 3, Aim 4, Aim 5, integrated manuscript summary, saved artifacts, reporting checklist.
3. **Aims 1–4 are placebo-session analyses.** Do not include oxytocin participants in Aims 1–4 unless explicitly labeled as a sensitivity or exploratory analysis.
4. **Aim 5 is the only full placebo/oxytocin model.** Aim 5 tests `Group * Drug` and should be interpreted as oxytocin modulation.
5. **Use the shared six primary neural metrics for Aims 2–5.** These are:
   - `Neural_Dist_Safety_Background`
   - `Neural_Dist_Threat_Safety`
   - `Neural_Decision_Margin_CSS`
   - `Neural_Decision_Margin_CSR`
   - `Neural_Safety_Trajectory_Slope`
   - `Neural_Threat_Trajectory_Slope`
6. **Aim 2 primary questions must stay separated.**
   - Q1 geometry: safety/background and threat/safety distances.
   - Q2 decision certainty: CSS and CSR decision margins.
   - Q3 learning dynamics: safety and threat trajectory slopes.
7. **Aim 3 clinical hierarchy must stay fixed.**
   - Primary clinical outcomes: `dass_anxiety`, `lsas_total`.
   - Support/contextual only: `lsas_fear`, `lsas_avoid`.
   - Do not use LSAS subscales to carry primary Aim 3 claims.
8. **Aim 4 SCR convergence must remain placebo-session physiological convergence.**
   - Primary SCR indices are `SCR_SafetyMinusBackground`, `SCR_ThreatMinusSafety`, `SCR_Safety_Trajectory_Slope`, and `SCR_Threat_Trajectory_Slope`.
   - SCR responder/learner cohorts are sensitivity populations, not replacement primary samples.
9. **Aim 1 primary inference is subject-aware permutation decoding.**
   - Primary tests: SAD-placebo self-decoding and HC-placebo self-decoding for `CSR` vs `CSS`.
   - Cross-group decoding and Haufe-map similarity are secondary mechanistic checks.
10. **Use correct multiple-comparison families.**
    - Aim 2: FDR within each planned scientific question.
    - Aim 3: FDR within diagnostic group across prespecified clinical-neural tests.
    - Aim 4: FDR within diagnostic group across prespecified SCR-neural tests.
    - Aim 5: use the model/export correction family already generated for `Group * Drug`.
11. **Missing optional outputs are not null results.** Whole-brain/Schaefer, MemoryFearNetwork, SCR subgroup, or manuscript-export files may be absent. Label them as missing/pending/unavailable, not as evidence of no effect.
12. **Prefer current CSV exports over legacy checkpoints.** Legacy checkpoint names are fallback-only and must trigger visible warnings.
13. **Prevent data leakage.** Scaling, feature selection, mask selection, hyperparameter selection, and model fitting must happen inside training folds in modeling scripts. The notebook audits this but cannot fully prove it.
14. **Subject-aware validation is required.** Use `StratifiedGroupKFold` or `LeaveOneGroupOut` for subject-aware CV in the source modeling scripts.
15. **Preserve figure/reporting conventions.**
    - Use colorblind-safe Okabe-Ito colors.
    - Center signed effects at zero when plotting effects.
    - Show individual subject points when available.
    - Save manuscript figures as both PNG and PDF under `stats/figures`.
16. **Do not silently drop rows or metrics.** If a planned metric/output is missing, keep an explicit missing-status row whenever possible.
17. **Keep notebook outputs audit-friendly.** Important tables should expose `status`, `n`, effect size, CI, p/q values, analysis label, feature space, group, drug, and formula when available.
18. **Do not overinterpret support/contextual analyses.** Use them to clarify specificity and mechanism, not to make primary claims.

## Editing rules for future revisions

### When adding a new result

- Add it under the correct aim.
- Decide its role before coding: primary, secondary/support/contextual, or sensitivity.
- Add missing-output behavior before adding display code.
- Add subject counts and feature-count metadata when relevant.
- Add or update the reporting checklist if the new result affects manuscript interpretation.
- Never make a new result visually prominent unless its inferential role is clear.

### When changing a metric

- Update the metric registry in Cell 4.
- Update any Aim 2 question mapping if the metric belongs to Aim 2.
- Update Aim 3/Aim 4/Aim 5 tables if the metric is part of the shared primary metric family.
- Update captions/Markdown cells so the interpretive hierarchy remains correct.
- Do not rename metrics only in plots; use a display-label mapping while preserving raw column names.

### When changing paths

- Keep `MVPA_L2_ROOT` as the first override.
- Keep local, Hyak, container, and relative output candidates unless they are truly obsolete.
- Update `PATHS` in Cell 4 and any feature-space-specific path helper together.
- If an output file is optional, missing status should be visible and non-fatal.

### When changing figures

- Keep PNG and PDF export.
- Keep figure filenames descriptive and aim-specific.
- Use signed effects centered at zero for effect plots.
- Keep color encodings consistent across the notebook: SAD vs HC and placebo vs oxytocin should not switch colors across figures.
- Show individual data points when subject-level data are available.
- Avoid making secondary or sensitivity figures look more confirmatory than primary figures.

### When revising statistical interpretation

- Confirm the sample restriction first.
- Confirm the multiple-comparison family.
- Confirm whether the result is primary or secondary.
- Report effect size and confidence interval before relying on p/q values.
- Do not interpret absent or pending sensitivity outputs as evidence for robustness or non-robustness.
- Preserve explicit caveats for manual confirmations, especially leakage prevention and hyperparameter/permutation provenance.

### When using Codex

Give Codex the following instruction before editing:

> Read `PROJECT_CONTEXT.md` and `mvpa_l2.md` first. Preserve the notebook’s aim order and primary/secondary/sensitivity hierarchy. Do not change the six primary neural metrics, clinical hierarchy, placebo-only scope for Aims 1–4, or Aim 5 `Group * Drug` scope unless explicitly requested. Make missing optional outputs visible rather than failing or interpreting them as null. Prefer current CSV exports over legacy checkpoints. Keep all changes minimal and localized.

## Final pre-run checklist

Before running or using `mvpa_l2.ipynb` for manuscript interpretation, confirm:

- `PROJECT_CONTEXT.md` exists and matches the analysis plan.
- `MVPA_L2_ROOT` points to the intended result directory, or one of the fallback paths is correct.
- `harmonized/mvpa_l2_subject_metrics.csv` exists.
- Primary Aim 1–5 CSV exports exist or missing outputs are clearly labeled.
- Subject counts and feature-count metadata are displayed before interpretation.
- Pipeline compliance audit has no unresolved critical issues, especially leakage-prevention concerns.
- Reproducibility table records paths, software versions, CV strategy, permutation metadata, and QC status.
- Aims 1–4 are placebo-only.
- Aim 5 is the only `Group * Drug` analysis.
- Primary clinical outcomes are `dass_anxiety` and `lsas_total`.
